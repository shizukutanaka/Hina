# 雛 (Hina) — 完成監査（イーロン・マスクのアルゴリズム適用・Round 526）

イーロン・マスクの5段階アルゴリズム（①要件を疑う ②部品/工程を削除 ③簡素化 ④サイクル加速 ⑤自動化、順序厳守）＋第一原理思考を雛に適用した記録。雛の非交渉制約（CLAUDE.md）の核心は「**単一HTML・依存ゼロ＝配布と監査の容易性**」であり、マスク法②「最良の部品は"部品なし"」はこの製品の存在理由に直結する。

## ① 要件を疑う（Question every requirement）

「要件は部門でなく個人から来る」の観点で、shipped されているものが本当に必要かを検査した。

- **i18nキー228個**: 全て参照されているか実測。→ **0個が dead**（後述）。要件は正当。
- **core の公開 export 41個**: 外部（app・tests）から本当に呼ばれるか実測。→ 2個が「防御的に export したが誰も使わない」＝**要件が個人でなく"習慣"由来**だった。削除対象（②へ）。
- **VRM 1.0 対応 / 指ボーン / プリセット追加**: FEATURE_AUDIT §3/§4 で既に「今は不要 or 視覚検証待ち」と判定済み。第一原理（3D非専門者をVRChatアバターまで最短で運ぶ）に照らし、v0.1スコープは妥当。

## ② 削除（Delete any part you can）

「10%を後で戻さないなら削り足りない」の精神で削除候補を実測。**ただし削除前に全動的参照を検証**（naive削除の罠を回避）。

| 対象 | 候補数 | 真に削除可 | 結果 |
|------|--------|-----------|------|
| i18nキー | 41（naive検出） | **0** | 全て `t(prefix+'.'+value)` 等の**動的参照**（`license.*`/`allowed.*`/`usage.*` は `selRow` の `t(tp+'.'+o)`、`guide.*` は配列ループ）。naive削除は許可/ライセンスUIを破壊していた |
| CSSルール | 3（`.row-less`等） | **0** | いずれも Round 497/498 の履歴を説明する**コメント内言及**で、実ルールではない。コメントは文脈として価値があり保持 |
| core export | 2（`SKIRT_OUTFITS`/`buildSkeleton`） | **2** | 内部使用のみ（`hasSkirt()`・`buildAvatar()` が内部で使用）で外部参照ゼロ。**定義は残し export のみ削除**（41→39）。公開面が縮小し監査負荷が減る |
| 共有状態 `px`/`py`（Round 528） | 2変数 | **2** | ポインタハンドラの共有アンカーが**最後の既知欠陥の原因そのもの**だった（2本目の指がアンカーを汚染→離すと視点が1.504rad跳ぶ、CDP実タッチで再現）。既存の `ptrs` Map が per-pointer で正しい位置を保持しているため、**共有変数を削除すると欠陥も消えた**。マスク法②の教科書例 |

**教訓（第一原理）**: 削除の前に「本当に未使用か」を実測で証明せよ。雛は動的参照（文字列連結でキー構築）が多く、`grep 't(\'key\')'` だけでは live なキーを dead と誤判定する。この罠を3回回避した（i18n・CSS・exportの各検査で正確な出現カウントに切り替えた）。

## ③ 簡素化（Simplify）— 削除の後にのみ

削除で1件の副作用（export削除でreturnブロックが伸び、正規表現ウィンドウ型テストの400字境界を越えて失敗）が出たため、説明コメントを`return {`の外へ移してブロックをコンパクトに保った。これは SWOT #4（正規表現ウィンドウ型テストの脆さ）の実例であり、テストを弱めず構造で解消。他に安全に簡素化できる過剰は検出されず＝**既に最小に近い**。

## ④ サイクル加速 / ⑤ 自動化

- **ビルド**: `cat build/* > index.html` の1コマンド。加速の余地なし。
- **テスト**: `node tests/run.js` が **2045件を約2秒**。十分高速。
- **検証の自動化**（Round 520）: `tools/render-check.js` が視覚回帰を自動判定。仕様適合（Round 515スイート）＋公式バリデータ（Round 524）＋参照ローダー three-vrm（Round 525）で多層自動化済み。
- **残る手動工程**: リポジトリ公開設定（default branch / Release / GitHub Pages）＝Settings権限が必要で**人間ゲート**。ここは自動化不能（SWOT #6）。

## 完成の評価（第一原理）

「完成」を「3D非専門者が、インストール不要・データを預けず・パフォーマンスゲートに阻まれず、VRChatアバターを手にできる」と定義すると:

- 生成・プレビュー・書き出し・導入ガイド（アプリ内自己完結・Round 512）・ランク保証・ワンタップ修正（Round 513）まで**すべて実装済み**。
- 出力は**公式 glTF-Validator で0 errors**、**参照ローダー three-vrm で完全読込**。
- コードは**実測で最小**（dead i18n/CSS/export ゼロ、export面を縮小）。

→ **プロダクトとしては完成**。残るのは人間ゲートの公開設定3点（各1–2クリック、SWOT改善案#1）のみで、これはコードの問題ではなく権限の問題。
