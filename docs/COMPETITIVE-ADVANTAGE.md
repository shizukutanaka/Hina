# Competitive Advantage — 雛 Hina (2026-11-22)

方法: 競争優位性プログラム。競合調査（有料・無料を問わず）→ お金の流れの
分解 → マスク思考法＋ソクラテス問答を、意味のある知見が出るまで反復
（2ラウンド実施）。判定の出発点は作成者の原則: 個人データを持たない／
提供はソフトウェアのみ（運営費を負担しない）／本体は無料。

アバター作成ツール自体に金は流れない。VRoid が無料＋商用OKで価格を

そしてサーバー依存のアバターは、保管者の終了と一緒に消える
（Ready Player Me は書き出し手段すら残らなかった）。

## 反復の記録

### ラウンド1 — 「手軽さ」を疑う

- 疑った前提: 価値はアバター作りの手軽さ（スライダー vs Blender）にある。
- 消えたもの: 「無料」「スライダー操作」そのもの（VRoid が同じ土俵で
  無料・高表現で先行）。「ブラウザで開ける」も正規形態がデスクトップ版の
  現行では主役にできない。
- 生き残ったもの: Performance Rank の合格が構造で保証されること
  （既定プリセットが Quest Excellent 圏にテストで固定され、VRoid は
  ランクを保証しない）。アバターがレシピ（シード・JSON・共有URL）と
  して再現・流通できること。保管者が存在しないこと。

### ラウンド2 — 削除テスト（前提が崩れた）

- プレビューを消しても製品は立つ。パラメトリック生成を消せば何も残らない。
- Rank 推定と合格保証を消すと、雛は「表現力で VRoid に劣る生成器」に
  なる。つまり存在理由は「作れること」ではなく「VRChat の性能ゲートを
  通ることが作る前から保証されていること」だった。
- 市場の競争軸は表現の豊かさだが、初心者が実際につまずくのはゲート
  （Quest でランクが落ちる・表示されない理由が分からない）であり、
  そこを保証する道具は競合に無い。
- 副次的知見: 「プラットフォームのアバターは保管者の死と一緒に消える」
  （Ready Player Me）への答え（ファイル＋シード）は既に実装済みだが、
  看板の主役になっていない。

## 構造的優位

雛は、アバターを「VRChat の性能ゲート合格が構造で保証された、シードと
いう再現可能なレシピ」として単一ファイルから生成し続けることができる。
競合の収益はマーケットプレイスの手数料かエコシステムへの囲い込みの
上に成り立ち、表現の豊かさで競う構造上、「合格保証＋保管者不在＋
レシピの流通性」には寄せられない。雛は収益もサーバーも持たないため、
その約束を無条件に、永続的に守れる。

補強する既存の実態:

- 既定6プリセットの Quest Excellent（揺れ物OFF）はテストで固定され、
  Rank 推定は公式基準（2026-04版）の全項目で行われる。
- 書き出しは標準 VRM 0.x ファイル。公式 glTF-Validator 0 errors と
  参照ローダー three-vrm の全ケース読込が実測済み。
- ガチャは決定論的で、シードと共有URLでアバターそのものが流通する。
  作成者は利用者のデータを一切持たない（通信ゼロを実ブラウザで実測済み）。
